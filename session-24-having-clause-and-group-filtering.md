# Session 24 Guide: SQL HAVING Clause & Group Filtering

This comprehensive lecture and reference guide covers the mechanics, execution order, structural differences, and practical application of the SQL **HAVING** clause for group filtering and complex aggregate queries.

---

## 1. HAVING vs WHERE: Execution Pipeline & Differences

Understanding the fundamental distinction between the `WHERE` clause and the `HAVING` clause requires examining the logical processing order of an SQL query.

### A. Logical Execution Order Pipeline
```
1. FROM / JOIN   -> Identifies source tables and performs relational joins.
2. WHERE         -> Filters individual raw table rows BEFORE aggregation.
3. GROUP BY      -> Groups surviving rows into summary buckets based on key columns.
4. HAVING        -> Filters summary groups AFTER aggregate calculations occur.
5. SELECT        -> Evaluates expressions and aliases for the output projection.
6. DISTINCT      -> Eliminates duplicate rows from the final result set.
7. ORDER BY      -> Sorts the final output rows.
8. LIMIT / OFFSET-> Restricts the number of returned rows.
```

### B. Structural & Behavioral Comparison Matrix

| Aspect / Feature | WHERE Clause | HAVING Clause |
| :--- | :--- | :--- |
| **Primary Purpose** | Filters individual candidate rows. | Filters summary groups generated by GROUP BY. |
| **Execution Timing** | Operates **BEFORE** `GROUP BY` grouping. | Operates **AFTER** `GROUP BY` grouping. |
| **Aggregate Functions** | **NOT Allowed** (e.g., `WHERE AVG(salary) > 50000` is invalid). | **Allowed & Intended** (e.g., `HAVING AVG(salary) > 50000`). |
| **Column Scope** | Can filter on any column in the source table. | Can filter on aggregate results or grouping columns. |
| **Index Usage** | Utilizes B-Tree indexes on source tables. | Evaluates on temporary grouped memory structures. |
| **Usage Without GROUP BY** | Filters rows from source tables. | Acts like `WHERE` over a single implicit global group. |

### C. Common Syntax Error: Invalid Use of Group Function
Attempting to place an aggregate function inside a `WHERE` clause causes an immediate SQL runtime error:

```sql
-- INVALID QUERY (Raises SQL Error 1111: Invalid use of group function)
SELECT department_id, AVG(salary)
FROM Employees
WHERE AVG(salary) > 60000 -- ERROR: Aggregate function not allowed in WHERE
GROUP BY department_id;

-- CORRECT QUERY (Uses HAVING for group aggregate filtering)
SELECT department_id, AVG(salary) AS avg_sal
FROM Employees
GROUP BY department_id
HAVING AVG(salary) > 60000; -- VALID: Filtering groups after aggregation
```

## 2. Group Filtering Mechanics

The `HAVING` clause allows developers and data analysts to set mathematical thresholds on aggregate values across summary groups.

### A. Basic Group Filtering Syntax
```sql
SELECT column_1, column_2, AGGREGATE_FUNCTION(column_3)
FROM table_name
WHERE row_condition
GROUP BY column_1, column_2
HAVING aggregate_condition;
```

### B. Single and Compound Group Filters
1. **Filtering by Group Count (`COUNT`):**
   ```sql
   -- Find departments with more than 5 active employees
   SELECT department_id, COUNT(employee_id) AS active_emp_count
   FROM Employees
   WHERE status = 'ACTIVE'
   GROUP BY department_id
   HAVING COUNT(employee_id) > 5;
   ```

2. **Filtering by Group Sum (`SUM`):**
   ```sql
   -- Find customers whose total purchases exceed $10,000
   SELECT customer_id, SUM(order_amount) AS total_spent
   FROM Orders
   GROUP BY customer_id
   HAVING SUM(order_amount) >= 10000.00;
   ```

3. **Compound Group Filters (`AND`, `OR`, `NOT`):**
   ```sql
   -- Find departments with > 3 employees AND average salary > $75,000
   SELECT department_id, COUNT(*) AS emp_count, AVG(salary) AS avg_salary
   FROM Employees
   GROUP BY department_id
   HAVING COUNT(*) > 3 AND AVG(salary) > 75000.00;
   ```

## 3. Complex Queries: Combining JOINs, WHERE, GROUP BY & HAVING

In production enterprise reporting, `HAVING` clauses are combined with relational `JOIN`s, row-level `WHERE` filters, sorting, and pagination.

### A. E-Commerce High-Value Customer Report
**Business Requirement:** Find active customers who placed more than 3 orders in 2026, with a total spend exceeding $5,000, ordered by highest spend.

```sql
SELECT 
    c.customer_id,
    c.customer_name,
    c.email,
    COUNT(o.order_id) AS total_orders_2026,
    SUM(o.total_amount) AS gross_spend_2026
FROM Customers c
JOIN Orders o ON c.customer_id = o.customer_id
WHERE o.order_date >= '2026-01-01' 
  AND o.order_date < '2027-01-01'
  AND o.order_status = 'COMPLETED'
GROUP BY c.customer_id, c.customer_name, c.email
HAVING COUNT(o.order_id) > 3 
   AND SUM(o.total_amount) > 5000.00
ORDER BY gross_spend_2026 DESC
LIMIT 10;
```

### B. Product Inventory Low-Stock Alert
**Business Requirement:** Identify product categories that have fewer than 50 total units in stock across all products, but have an average unit price over $100.

```sql
SELECT 
    p.category_id,
    cat.category_name,
    COUNT(p.product_id) AS product_count,
    SUM(p.stock_quantity) AS total_units_in_stock,
    ROUND(AVG(p.unit_price), 2) AS avg_unit_price
FROM Products p
JOIN Categories cat ON p.category_id = cat.category_id
GROUP BY p.category_id, cat.category_name
HAVING SUM(p.stock_quantity) < 50 
   AND AVG(p.unit_price) > 100.00
ORDER BY total_units_in_stock ASC;
```

## 4. Query Practice & Debugging Exercises

### Problem 1: Popular University Courses
**Prompt:** Write a query to find all course sections in Semester 1 that have more than 30 enrolled students and an average student grade higher than 85.0.

```sql
SELECT 
    e.section_id,
    c.course_code,
    c.title,
    COUNT(e.student_id) AS enrolled_students,
    ROUND(AVG(e.numeric_grade), 2) AS avg_section_grade
FROM Enrollments e
JOIN Class_Sections cs ON e.section_id = cs.section_id
JOIN Courses c ON cs.course_id = c.course_id
WHERE cs.semester = 'Semester 1'
GROUP BY e.section_id, c.course_code, c.title
HAVING COUNT(e.student_id) > 30 
   AND AVG(e.numeric_grade) > 85.00
ORDER BY avg_section_grade DESC;
```

### Problem 2: Top Performing Sales Representatives
**Prompt:** Find sales representatives who have closed at least 10 deals with a total deal value exceeding $100,000, excluding deals flagged as 'CANCELLED'.

```sql
SELECT 
    sr.rep_id,
    sr.rep_name,
    COUNT(d.deal_id) AS closed_deals,
    SUM(d.deal_amount) AS total_revenue
FROM Sales_Reps sr
JOIN Deals d ON sr.rep_id = d.rep_id
WHERE d.status <> 'CANCELLED'
GROUP BY sr.rep_id, sr.rep_name
HAVING COUNT(d.deal_id) >= 10 
   AND SUM(d.deal_amount) > 100000.00
ORDER BY total_revenue DESC;
```

### Problem 3: Debugging Incorrect SQL
**Flawed Query:**
```sql
-- FLAWED QUERY
SELECT department_id, COUNT(*) AS emp_count
FROM Employees
WHERE status = 'ACTIVE' AND COUNT(*) > 5 -- ERROR!
GROUP BY department_id;
```

**Correction & Explanation:**
The condition `COUNT(*) > 5` is an aggregate filter and cannot be placed in the `WHERE` clause. It must be moved to a `HAVING` clause following `GROUP BY`.

**Fixed Query:**
```sql
SELECT department_id, COUNT(*) AS emp_count
FROM Employees
WHERE status = 'ACTIVE'
GROUP BY department_id
HAVING COUNT(*) > 5;
```

## 5. Summary Cheat Sheet

| Query Clause | Operational Level | Primary Filtering Target | Accepts Aggregate Functions? |
| :--- | :--- | :--- | :--- |

| **`HAVING`** | Group-level | Aggregated summary buckets | **YES** |
